## Comparison sources

These local trees sit alongside the AdvCiv-SAS installation in the Civ4 `Mods` directory. Current AdvCiv-SAS source and Git establish what the mod does today.

- `AdvCiv` (1.14) is the direct comparison for current base AdvCiv behavior.
- `K-Mod` (1.46 master snapshot) helps check inherited behavior. Use the K-Mod commit diffs for changes over time.
  - The `KMod` commits in this history end at `d0a60f8b9` (2016-11-04), one commit after version 1.45 (`fa1dc9eaf`, 2016-10-05), so the changes made for 1.46 are only in the local snapshot.
  - The first 27 commits (2010-12-27 to 2011-04-26) carry `git-svn-id: svn://localhost/civ4`, so they came from an SVN on the developer's own machine. We found no public K-Mod SVN to export, unlike Better BTS AI, and those commits are already in `commit_diffs`.
- `civ4betterai-code-r597-trunk/CvGameCoreDLL` (Better BTS AI, SVN trunk at r597; latest SourceForge release we found [1.01](https://sourceforge.net/projects/civ4betterai/files/Better%20BTS%20AI/Better%20BTS%20AI%201.01/), 2010-07-01) helps check whether behavior seen in K-Mod was already present in Better BTS AI.
  - Use the SVN diffs below for changes over time. [SVN r597 archive](https://sourceforge.net/p/civ4betterai/code/597/tarball?path)
  - [`LLM_Helpers/context/svn_history/bbai/`](/LLM_Helpers/context/svn_history/bbai/INDEX.txt) holds the whole SVN history (r1-r597, 2006-10-14 to 2010-09-04) as one greppable diff per revision, for questions older than K-Mod's first snapshot (2010-12-27).
    - It covers the Firaxis SDK drops 1.61, 2.0, 2.08 and 3.17, the early AI work by iustus and blakeciv (2006-2007) and jdog5000's Better BTS AI (2008-2010).
    - The record has a gap from 2007-03 to 2008-07, and Better BTS AI enters at release 0.35 (r378-r379), so its earlier releases are not in SVN.
    - We rely on SVN rather than the 1.01 release (r590): it has the per-revision diffs and goes further, by six revisions and about two months, to r597 (2010-09-04).
  - How it reached us: f1rpo pointed to this SourceForge repository in the Advanced Civ thread on CivFanatics, recalled as mid to late 2026, after wonderingabout mentioned the C++ File Audit Album and the historical archaeology.
    - wonderingabout first took the link for the Better BTS AI documentation we already had, which is far less useful for archaeology.
    - The source history was retrieved on 2026-11-09, when KI#771.2 needed evidence older than K-Mod.
    - This export picks up the thread f1rpo started in that discussion, carrying the album and archaeology work back to the history before K-Mod.
  - Why it is tracked, unlike `commit_diffs`: that corpus was untracked by the 2026 history rewrite because it was large, redundant with Git and changed often (f1rpo valued it enough to salvage a copy first, with a Claude-authored script).
    - This export is small, frozen since 2010 and absent from our Git history, so it follows `mapscript_refs` instead.
    - It is a text copy of that history, not joined to our Git ancestry, so `git log` does not reach it.

- `Civ4CE-main/BtS/CvGameCoreDLL` supports comparisons with the original Beyond the Sword SDK. [Civ4CE](https://github.com/f1rpo/Civ4CE)

How to read it:

- These measure credited comments, not code written or effort. A commit counts once per model, whatever its size.
- `Commits` and `Credited lines` count every commit adding a line with that credit, so a comment that was moved or reworded counts again.
- `Inline mentions` counts added comment lines naming a model in their prose rather than in the closing credit, such as "advised by chatgpt 5". Older comments mostly credit models this way, so it matters most for the early rows. A mention can also merely refer to a model, and rewrites count again here too.
- `Doc mentions` counts added Markdown and text lines naming a model, such as credits in Known Issues. Generated logs, changelogs, examples and `AGENTS.md` are skipped, and so are the C++ File Audit Album and other records in this folder, because commit diffs exclude them. Docs also refer back to old models, so this column is the loosest.
- `First credit` is the first closing credit, inline mention or doc mention, whichever came first.
- `Last new credit` is the last commit that added more lines with that credit than it removed, so such a rewrite nets to zero.
  - Only the last-named model in a credit counts, because credits are appended, and test fixtures are skipped. Without that, the 2026-10-10 comment reflow made GPT-5.3-Codex look active long after its last real work.
  - It is still an approximation. A model editing its own comment nets to zero, a comment replaced by a different one in the same commit is missed, and a late date can still come from a comment re-homed from elsewhere. Commit titles are the cross-check: `-` means no commit added more than it removed.
- Labels stay as credited. Capitalization and punctuation variants count as one, and notes about the work such as `(summarized)` or `review` are ignored.
  - Misspellings found in the history are merged too, such as `chagpt` and `chtagpt`, with `3-o` and `o-3` read as `o3`. A standalone `o3` or `4o` counts as ChatGPT.
  - `Claude code`, `Claude`, `Claude AI`, `GPT-`, `ChatGPT-` and `Thinking` stay separate. `GPT-` usually means Codex and `ChatGPT-` web chat.
