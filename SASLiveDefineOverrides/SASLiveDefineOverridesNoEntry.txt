# <!-- custom: Defines that SASLiveDefineOverrides.txt must not override, each named in full with its reason, so a grep for a define finds its line; patterns such as SAS_EXE_P_* were expanded on 2026-11-26 at the user's request, and CI now rejects a "*".
# The bridge reads it once with the XML and rejects a SASLiveDefineOverrides.txt line naming a listed define, logging its reason, and CI's sas_live_define_overrides.py fails a shipped one. Until 2026-11-26 it was a signpost only CI enforced, so a local line could still change a listed define, leaving a reader that ignores it out of step with one that follows it, as Codex's review (GPT-6.2-Sol) noted; Codex then advised the in-game check.
# It is not exhaustive: it lists the defines that should not be overridden, not every define an override would miss. Many others are kept in a DLL static or a Python attribute, so an override reaches them only once their readers change; LLM_Helpers/audits/audit_define_timing.py lists each define's readers and how they read it.
# Since KI#128.7 (2026-11-26) the bridge refuses any define not in SASLiveDefineOverridesAllowed.txt, so such a define is refused too, with a general reason; this file keeps the specific reasons, which the refusal prints first, and no define may be in both.
# One define per line, its name, a colon and the reason, which CI requires; a family's later lines say "same reason as" its first rather than repeat it, as the user suggested to cut churn; "#" starts a comment line.
# Settings whose timing was not checked, such as FastSave's or the Dawn of Man screen's, are left out rather than guessed. See KI#128.5. (Claude code Opus 5.5 + GPT-6.2-Sol) -->

SAS_LIVE_DEFINE_OVERRIDES_ON: the switch of the overrides themselves, read once when the bridge first loads
SAS_BBAI_LOG_ON: a master switch, which decides at startup whether the session's log file exists
SAS_SGR_LOG_ON: a master switch, which decides at startup, with SAS_SGR_LOG above 0, whether the session's record file and its baseline rows exist
SAS_SGR_LOG: the record's detail level, fixed per record: raising it skips baselines written only at the record's start, and lowering it leaves RNG tracking and tracked wars inconsistent, as Codex's review (GPT-6.2-Sol) found; a sound change would apply from the next record
SAS_RUNTIME_STATUS_ON: a master switch, which decides at startup whether the runtime status files exist
SAS_RUNTIME_SOURCE_WATCH_ON: a master switch, which starts the source watcher at launch
SAS_RUNTIME_SCREENSHOT_WATCH_ON: a master switch, which starts the screenshot watcher at launch
SAS_BBAI_LOG_USE_TIMESTAMPED_FILENAME: it names the BBAI log file when the file opens
SAS_SGR_LOG_USE_TIMESTAMPED_FILENAME: it names the SASGameRecord file when the file opens
SAS_SGR_REVISION: a revision label, which names SASGameRecord's version rather than tuning it
SAS_RUNTIME_REVISION: a revision label, which names Runtime's version rather than tuning it
SAS_SAVE_VERSION: copied to SAVE_VERSION at XML load, which saves and CvReplayInfo then read
SAS_ASSERT_SILENT_ACTION: cached once at XML load by cacheSASAssertionSilentPolicy in FAssert.cpp, which decides how assertion dialogs are answered for the session
SAS_LEADER_XML_ERA_ART_DEFS: decides at XML load, in a static in CvInfo_Civilization.cpp, whether leaders' EraArtDefineTags are parsed, so turning it on later cannot bring back skipped tags, and turning it off would hide era art the DLL still holds; the Sevopedia's leader page reads it at use since KI#128.6, as Codex's review (GPT-6.2-Sol) noted
SAS_LAUNCH_GUARD_TEST_INT: a launch guard value, which exists to prove the XML loaded
SAS_LAUNCH_GUARD_TEST_STRING: same reason as SAS_LAUNCH_GUARD_TEST_INT

SAS_EXE_P_ON: an EXE patch switch, which decides whether the running game's code is rewritten, so flipping it during play is risky; some patches, such as the plot indicator and help text area ones, can be applied again, but a define edit does not reliably apply or undo a patch, as Codex's review (GPT-6.2-Sol) found; Realism Invictus's SelfMod.cpp (r5656), where these patches come from, likewise marks some of its patches as applying only after a restart and others as live, as the user recalled Walter Hawkwood saying
